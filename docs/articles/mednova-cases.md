# 教程案例

## MedNova Cases

常见医学研究任务如何在 Studio 中完成“输入数据 -\> 选择任务 -\>
配置当前任务输入 -\> 生成脚本”的流程，都汇总在这页。

## 案例 1：PSM 案例

### 输入数据长什么样

- 一张患者级临床表
- 至少包含治疗 / 暴露列
- 至少包含若干协变量，如年龄、性别、BMI、合并症等

### 在 Studio 里怎么填

- 任务类型：`PSM`
- 任务备注可写：`love plot`
- 治疗 / 暴露列：选择 `treatment`
- 协变量 / 预测变量：选择需要纳入匹配模型的临床变量

### 生成的代码会是什么类型

- 以 PSM 为主的 R 脚本
- 以 [`med_psm()`](https://example.com/MedNova/reference/med_psm.md)
  为主入口
- 可包含匹配、baseline table、balance table 与 love plot 输出

### 常见注意事项

- 不要把结局列误当成协变量
- 协变量应尽量是治疗前信息

## 案例 2：Logistic 案例

### 输入数据长什么样

- 一张临床表
- 至少包含二分类结局列
- 还需要若干预测变量

### 在 Studio 里怎么填

- 任务类型：`Logistic`
- 任务备注可写：`odds ratio output`
- 结局列：选择二分类结局
- 协变量 / 预测变量：选择候选变量

### 生成的代码会是什么类型

- 多因素 Logistic 回归脚本
- 以
  [`med_logistic()`](https://example.com/MedNova/reference/med_logistic.md)
  为主入口
- 可包含单因素、多因素和 OR 风格结果输出

### 常见注意事项

- 结局列需要可解释为二分类
- 不要把 ID 列或纯标签列当作预测变量

## 案例 3：Cox 案例

### 输入数据长什么样

- 一张生存分析用临床表
- 包含时间列与事件列
- 包含候选协变量

### 在 Studio 里怎么填

- 任务类型：`Cox`
- 任务备注可写：`overall survival`
- 时间列：选择随访时间或生存时间字段
- 事件列：选择事件状态字段
- 协变量 / 预测变量：选择年龄、分期、评分等变量

### 生成的代码会是什么类型

- Cox 比例风险模型脚本
- 以 [`med_cox()`](https://example.com/MedNova/reference/med_cox.md)
  为主入口
- 包含时间到事件模型与风险比结果输出结构

### 常见注意事项

- 时间列与事件列不要混淆
- 事件列最好明确为 0/1 或两类状态

## 案例 4：MR 案例

### 输入数据长什么样

- 暴露与结局的 GWAS 汇总统计
- 常见字段包括 `snp`、`beta`、`se`、`pval`、等位基因相关列等

### 在 Studio 里怎么填

- 任务类型：`MR`
- 当前版本更适合在上传前先整理好 exposure / outcome 数据对象
- 逐项选择 SNP、beta、SE、P 值和等位基因相关字段

### 生成的代码会是什么类型

- MR 流程脚本骨架
- 以 [`med_mr()`](https://example.com/MedNova/reference/med_mr.md)
  为主入口
- 包括 exposure / outcome 处理、协调与主分析调用

### 常见注意事项

- 如果数据其实是 clinical table，平台会提示结构不匹配
- MR 常常需要比普通临床表更多的结构化统计字段

## 案例 5：诊断模型案例

### 输入数据长什么样

- 一张包含二分类结局和候选特征的表
- 或者表达数据与分组信息的组合

### 在 Studio 里怎么填

- 任务类型：`Diagnostic`
- 任务备注可写：`roc`
- 结局列：选择疾病状态或诊断标签
- 协变量 / 预测变量：选择特征列或基因特征

### 生成的代码会是什么类型

- 诊断模型脚本
- 以
  [`med_diagnostic_model()`](https://example.com/MedNova/reference/med_diagnostic_model.md)
  为主入口
- 常包含模型、性能输出与 ROC 相关结果

### 常见注意事项

- 结局列必须足够清晰
- 特征数量较多时，建议先人工筛选再生成脚本

## 如何把案例迁移到真实项目

无论哪个案例，都建议使用以下平台步骤：

1.  先选择任务类型
2.  再手动配置当前任务输入
3.  查看函数需求中的缺失输入
4.  最后导出脚本并人工复核
